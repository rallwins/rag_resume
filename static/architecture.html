How Resume Room works

A resume is indexed into a local knowledge base. Questions retrieve relevant passages first; only evidence above the similarity threshold is sent to the Ollama answer model.

4 · Return answer and diagnostics

Browser displays the answer, grounding score, token counts, latency, throughput, and source.

Local inference

Embeddings and answer generation use Ollama. The app binds to localhost by default.

Evidence gate

Weak retrieval is refused before generation. The model is instructed to use only supplied resume passages.

Metadata-only tracing

When configured, Langfuse receives grounding status, similarity, token usage, and timings, not resume text or the raw question.

What each answer reports

Request logs and the chat response expose diagnostics for inspection. Similarity is a retrieval signal, not a statistical precision score.

RETRIEVALTop cosine similarity, configured threshold, grounding state, and matched source.
TOKEN USAGEPrompt, completion, and total tokens reported by Ollama.
LATENCYPrompt evaluation, generation, and total request time.
THROUGHPUTGenerated tokens per second plus a request ID for log correlation.

The retrieval threshold and prompt instructions are defense in depth, not a guarantee against all prompt injection. Review answers before relying on them for high-impact decisions.
